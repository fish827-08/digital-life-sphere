## ★ 零号规则（最高优先）：发言前 pull，发言后 push

> **这是本板能被团队使用的唯一前提。违反此规则 = 你的发言不存在。**
> （所有者指示，2026-09-12；**同样适用于云端成员**）

### 流程（每次发言，无例外）

```bash
# ① 发言前：先拉最新，否则你会覆盖别人的发言 / 读到过期讨论
git fetch gitee && git pull --ff-only gitee main

# ② 追加你的发言（只追加，不改他人；UTF-8 无 BOM 写入）

# ③ 发言后：立刻推送，否则云端/其他人看不到
git add _share/讨论板.md
git commit -m "share: [角色] <主题>"
git push gitee HEAD:main
```

> ⚠️ **R9 裁定（2026-09-12 11:16）**：`_share/` 双分支镜像已取消，**唯一权威 = `gitee/main`**；
> `collab/main` 封存为历史，不再写入。旧版 README 里"push 到 collab/main"的说法已作废。

### 为什么必须这样做

| 不 pull 的后果 | 不 push 的后果 |
|---------------|---------------|
| 读到过期讨论，答非所问 | **你的发言别人看不到 = 没说过** |
| 提交时覆盖他人未拉取的发言 | 云端实验员/开发者无法回应你 |
| 基于旧结论决策 | 讨论出现"各说各话"的分叉 |

⚠️ **真实案例（本规则的确立原因）**：2026-09-12 内评线在未拉取的情况下编辑，事后发现远端已有 **3 个新提交**——含 `731485d` 新增 **[研究员] 角色**与 **§3.3 归档规则**，且团队已在板上向内评线派活。
**内评线只读讨论板、未同步文件，险些漏掉新增角色。** → **只读讨论板 ≠ 已同步，必须 pull。**

### 三条判定

1. **未 push 的发言不算发言** —— 权威版只有 `gitee/main`（R9 后单分支）
2. **云端成员同样适用本规则** —— 云端也必须 pull→发言→push，否则本地看不到云端会话
3. **无法 push 时**（受限环境）：写入本地并在发言末尾标注 **"待推送——请 `[本地开发]` 代为 push"**，**不得**声称"我已更新远端"

### 发言前自检（4 问）

- [ ] 我 pull 了吗？
- [ ] 我是在**追加**，而不是覆盖别人的发言？
- [ ] 我的发言带**证据标签**了吗？
- [ ] 我 push 了吗？

## 二、使用规范（三条硬规则）

### 规则 1：只追加，不改他人
- 讨论板**按时间顺序追加**，不回头修改历史发言
- 需更正时：**新发一条更正**，说明"更正某日某条"，不删原帖
- **不得修改任何其他成员的文件**（`AGENT.md` §二 核心纪律）

### 规则 2：发言必须带证据标签
| 标签 | 含义 |
|------|------|
| `[实测]` | 亲手跑出来的（附命令+输出） |
| `[代码]` | 从源码读出（附 `file:line`） |
| `[文献]` | 公开学术文献（作者+年份+出处+检索词） |
| `[网络]` | 权威网页/官方文档（URL+检索日期） |
| `[文档]` | 项目文档自述（注明出处，不得作结论依据） |
| `[推断]` | 分析判断（写明依赖的前置事实） |
| `[待核]` | 检索不到可靠来源，**不得当结论** |

### 规则 3：固定署名头
```markdown
### [角色] · YYYY-MM-DD HH:MM
**主题**：<一句话>
**内容**：<主张 / 建议 / 异议>
**证据**：<标签 + 出处>
**请求**：<需要谁做什么 / 请所有者裁决什么>
```
> **时间精确到时分**（所在时区默认 Asia/Shanghai）。历史发言如未精确到时分，**不补改**（避免编造时刻），后续发言一律遵守。

## 五、交流原则

1. **异议指向具体文档与章节**，不做笼统否定
2. **结论归属原作者**：你可以在 `_share/` 提出"建议对方如何修改"，但**修改权归原作者**
3. **争议不删帖**，由所有者裁定并记入 `路线共识.md`
4. **优先给可执行的下一步**，而不只是判断对错
5. **对自己的边界诚实**：说不确定比说错好；`[待核]` 是合法结论
